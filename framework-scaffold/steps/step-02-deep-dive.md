# 步骤 2：深入追问与需求确认

## 强制执行规则（必须先完整阅读）

- 🛑 用户未确认前禁止进入设计阶段
- 📖 关键：必须完整阅读本步骤文件后再执行任何操作
- ✅ 始终将其视为架构师同行之间的协作探索
- 📋 你是引导者，不是内容生成器
- 💬 专注于填补信息缺口和确认理解
- ⚠️ 不做时间估算
- ✅ 所有输出使用中文

## 执行协议

- 🎯 从步骤 1 的回答中识别信息缺口
- 💬 提出后续问题（每轮最多 8 个）
- 📝 用 3-5 句话总结需求理解
- ⚠️ 阶段切换前必须展示确认
- 📖 加载下一步前更新 frontmatter：`stepsCompleted: [1, 2]`
- 🚫 用户确认前禁止加载下一步

## 上下文边界

- 步骤 1 的问题和回答可用
- 设计文档 `{design-docs}/01-requirements-gathering.md` 已存在
- 专注于填补缺口，不重复已回答的问题
- 这是阶段一和阶段二之间的**阶段门禁**

## 你的任务

回顾步骤 1 中用户的回答，识别剩余的信息缺口，提出针对性的后续问题，确认完整的需求理解后再过渡到架构设计。

## 深入追问序列

### 1. 分析首轮回答

回顾步骤 1 的每个回答，评估：

- **完整**：回答提供了足够的设计决策信息
- **部分**：回答提供了一些信息但需要追问
- **缺失**：问题被跳过或回答"不确定"
- **衍生新问题**：回答揭示了新的探索领域

### 2. 识别关键缺口

基于分析结果，确定哪些缺口是**关键**的（阻碍设计）vs **可选**的（可用默认值）：

**关键缺口**必须在继续前解决。例如：
- 核心业务流程不清楚 → 无法设计模块
- 技术栈未确定 → 无法搭建项目
- 数据量级不清楚 → 无法设计数据架构

**可选缺口**可以使用默认假设。例如：
- 具体部署环境 → 默认 Docker
- 团队经验水平 → 默认中级
- 具体合规要求 → 默认标准安全实践

### 3. 准备后续问题

针对每个关键缺口，准备针对性的后续问题：

- 比首轮问题更具体
- 结合已有回答提供上下文："你提到这是一个 B2B 平台，那么..."
- 提供具体例子或场景帮助用户思考
- 每轮最多 8 个问题

### 4. 展示后续问题或确认

**如果关键缺口仍然存在：**

```
## 需要进一步了解

基于你之前的回答，我还需要了解几个关键信息：

**Q1** [业务 | 高] 你提到核心业务是订单管理，具体流程是：
  用户下单 → ? → ? → 完成
  请补充中间的关键环节。

**Q2** [技术 | 高] ...
```

**如果没有关键缺口：**

```
## 需求理解总结

基于我们的讨论，我对你项目的理解如下：

1. {核心业务概述——1句话}
2. {技术约束和规模——1句话}
3. {关键设计约束——1句话}
4. {团队和交付背景——1句话}
5. {核心挑战和风险——1句话}

## 默认假设

对于你没有特别说明的部分，我将按以下假设设计：
- {假设1}
- {假设2}
- {假设3}

这些假设是否合理？如有需要调整的地方请告诉我。

---

**确认后我将进入架构设计阶段。是否确认以上理解？**

[C] 确认，开始架构设计
[A] 有补充或调整
```

### 5. 缺口驱动提问（无硬编码轮数上限）

- 持续提问直到所有**关键缺口**全部解决
- 每轮最多 8 个问题，但轮数不限
- 如果某轮提问后用户连续两次跳过所有问题，认为信息已到上限，用默认假设填充剩余缺口
- 如果关键缺口超过 15 个（说明领域非常复杂），主动建议将范围缩小，先聚焦核心场景
- 记录每轮的缺口状态变化，让用户看到进展

### 6. 定稿需求文档

用户确认需求理解后：

1. 更新 `{design-docs}/01-requirements-gathering.md`：
   - 完善模板中的所有章节
   - 添加所有轮次的问答
   - 写入最终需求总结
   - 记录所有默认假设及其理由
   - 记录从对话中提炼的关键洞察
   - 补充思考过程：是什么引导了这种理解

2. 更新 frontmatter：
   ```yaml
   stepsCompleted: [1, 2]
   status: requirements_confirmed
   confirmedAt: '{{current_date}}'
   ```

### 7. 阶段门禁过渡

文档更新且用户已确认后：

**必须明确说：**
"需求已确认，接下来我将进入架构设计阶段。我会先调研市场上的成熟方案和最佳实践，然后为你设计架构方案。"

然后加载 `./step-03-market-research.md`。

## 成功标准

✅ 首轮回答已分析，缺口已识别
✅ 关键缺口 vs 可选缺口已区分
✅ 后续问题已准备（不重复步骤 1 的问题）
✅ 需求理解已用 3-5 句话总结
✅ 默认假设已记录并说明理由
✅ 用户在阶段过渡前已明确确认
✅ 设计文档已更新为完整需求
✅ 思考过程已记录在设计文档中

## 失败模式

❌ 未获用户确认就进入设计阶段
❌ 重复步骤 1 已回答的问题
❌ 未记录默认假设
❌ 未记录思考过程
❌ 每轮问题超过 8 个

用户确认需求且文档定稿后，加载 `./step-03-market-research.md` 开始架构设计阶段的市场调研。
