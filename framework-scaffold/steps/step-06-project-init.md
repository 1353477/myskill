# 步骤 6：项目初始化

## 强制执行规则（必须先完整阅读）

- 📖 关键：必须完整阅读本步骤文件后再执行任何操作
- ✅ 所有生成的文件必须完整且语法正确
- 🔧 构建文件必须包含精确的依赖版本号
- 📁 目录结构必须与架构设计完全一致
- ✅ 所有输出使用中文

## 续建检查

在开始前检查已有状态：
- 读取 `{design-docs}/04-project-init.md`，检查 frontmatter 中的 `stepsCompleted`
- 如果 `stepsCompleted` 已包含 6，直接加载 `./step-07-code-generation.md`
- 如果步骤 1-5 的设计文档存在但未完成，提示用户先完成前置步骤
- 如果项目目录已存在（改造模式），扫描已有文件，只创建缺失的部分
- 如果工作流状态是 `design_confirmed`，正常从步骤 6 继续执行

## 上下文边界

- 步骤 5 确认了架构设计
- 步骤 3 验证了技术栈和版本
- 步骤 4 定义了模块划分
- 只关注项目初始化——模块代码在步骤 7 中生成

## 你的任务

基于确认的架构设计，创建目录结构、构建文件、配置文件和主启动入口。

## 初始化序列

### 1. 确定项目位置

询问用户项目创建位置：

"架构方案已确认。我准备开始搭建项目。

项目创建在哪里？
- 当前目录下的子目录 `{project-root}/{project_name}/`
- 其他位置（请指定）"

### 2. 创建目录结构

基于步骤 4 中确认的架构设计创建目录结构。

**`data/code-templates/{stack}.md` 中的目录结构是参考起点**，不是必须照搬。如果用户的架构设计与模板不同，以架构设计为准。

设计目录时遵循以下原则：
- 目录结构应该反映业务模块划分，而不是技术分层
- 用户在步骤 1-2 中提到的特殊需求（如多租户、国际化）应该有对应目录
- 改造模式下，尊重现有目录结构，只做增量调整
- 如果用户对目录组织有明确偏好，以用户偏好为准

### 3. 生成构建文件

写入包含所有依赖精确版本的构建文件：

**Spring Boot** → `pom.xml` 或 `build.gradle`
- Spring Boot starter 依赖
- 数据库驱动
- 参数校验
- Lombok（如适用）
- 测试依赖
- 插件配置

**NestJS** → `package.json`
- NestJS 核心
- 数据库 ORM（Prisma/TypeORM）
- 参数校验
- 测试工具
- 脚本：start、dev、build、test、migration

**FastAPI** → `pyproject.toml` 或 `requirements.txt`
- FastAPI + uvicorn
- SQLAlchemy + Alembic
- Pydantic
- 测试依赖

### 4. 生成配置文件

**Spring Boot** → `application.yml` + `application-dev.yml`：
- 服务端口
- 数据库连接（默认 localhost + Docker 服务名）
- JPA/Hibernate 设置
- 日志配置
- Actuator/健康检查

**NestJS** → `.env.example` + config 模块：
- 数据库连接字符串
- 应用端口
- 环境标识

**FastAPI** → `.env.example` + `app/config.py`：
- 数据库 URL
- 应用设置
- CORS 源

### 5. 生成主启动入口

写入完整的主启动入口：

**Spring Boot** → `{ProjectName}Application.java`
- `@SpringBootApplication` 注解
- `public static void main` 方法
- 包声明和 import

**NestJS** → `src/main.ts`
- NestFactory 引导
- CORS、参数校验管道、日志
- 端口配置

**FastAPI** → `app/main.py`
- FastAPI 应用创建
- CORS 中间件
- 路由注册
- 健康检查端点
- 生命周期事件

### 6. 复制设计文档

将步骤 1-5 中创建的设计文档复制或引用到新项目的 `docs/design/` 目录。

## 文件生成规则

- 使用 Write 工具创建每个文件
- 所有 import 必须存在且正确
- 所有注解/装饰器必须完整
- 初始化文件中不能有 "..." 或 "// TODO here" 占位符
- 配置必须包含合理的默认值（localhost、标准端口等）
- .gitignore 必须适合对应技术栈

## 成功标准

✅ 完整目录结构与架构设计一致
✅ 构建文件包含精确版本号，语法正确
✅ 配置文件包含合理的默认值
✅ 主启动入口完整且可运行
✅ .gitignore 适合技术栈
✅ 设计文档已复制到项目
✅ 项目初始化文档包含理由说明
✅ 所有文件语法正确

## 失败模式

❌ 缺少目录或文件
❌ 构建文件缺少依赖或版本错误
❌ 配置文件有硬编码或缺失值
❌ 启动入口无法编译/运行
❌ 未记录结构选择的理由
❌ 创建了与具体架构不匹配的通用结构
