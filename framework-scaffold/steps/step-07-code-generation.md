## 你的任务

为架构设计中定义的每个模块生成完整骨架代码，以及共享基础设施代码（异常处理、健康检查、日志）。生成所有实体的数据库迁移脚本。

## 代码模板引用

根据技术栈加载对应的代码模板文件作为**参考起点**：
- **Spring Boot** → 读取 `data/code-templates/spring-boot.md`
- **NestJS** → 读取 `data/code-templates/nestjs.md`
- **FastAPI** → 读取 `data/code-templates/fastapi.md`

每个模板文件包含常见项目的各层代码示例。

**重要：模板只是参考。** 实际生成代码时，必须根据：
- 用户在步骤 1-2 中确认的具体需求
- 步骤 4 中确认的架构设计（模块划分、分层方式、技术选型）
- 用户的偏好和反馈

来决定最终的代码结构、命名约定和分层方式。如果架构设计与模板冲突，以架构设计为准。如果用户有明确偏好，以用户偏好为准。

## 代码生成序列

### 1. 加载代码模板

读取对应技术栈的模板文件，理解各层代码的命名约定和结构。

### 2. 生成共享/通用组件

按模板中的顺序生成：
- 全局异常处理器
- 统一响应包装器
- 请求日志拦截器/中间件
- 健康检查端点

### 3. 为每个模块生成代码

对架构设计中的每个模块，按模板生成：
- Entity/Model（含标准字段和 TODO 业务字段）
- Repository/DAO（含基础 CRUD）
- Service（接口 + 实现，TODO 标注）
- Controller/Router（标准 CRUD 端点）

### 4. 生成数据库迁移脚本

按模板生成所有实体的初始迁移脚本。

### 5. 更新主启动入口

注册所有模块、全局组件、CORS。

### 6. 创建代码生成文档

写入 `{design-docs}/05-code-generation.md`，记录：模块清单、代码组织约定、数据库设计、思考过程。

### 7. 向用户展示进度

"模块代码生成完成。已生成以下内容：

🏗️ **{模块数} 个模块**：{模块名称列表}
🗄️ **数据库迁移**：{迁移文件}
🔧 **共享组件**：全局异常处理、健康检查、请求日志

[C] 继续，生成 Docker 环境
[A] 我想调整某些模块的代码结构"

## 代码质量规则

- 业务逻辑方法包含 `// TODO: 实现具体逻辑` 并返回合适的默认值
- 所有类有正确的包/命名空间声明
- 所有 import 完整且正确
- REST 端点遵循一致的命名：`/api/{资源}` 标准 CRUD
- 全程使用依赖注入（优先构造器注入）
- DTO 与 Entity 分离（在需要的地方）

## 成功标准

✅ 所有模块有完整的骨架代码（Entity + Repository + Service + Controller）
✅ 全局异常处理器已生成
✅ 健康检查端点已生成
✅ 请求日志拦截器/中间件已生成
✅ 数据库迁移脚本语法正确
✅ 所有代码可编译通过
✅ 代码生成文档包含理由说明

## 失败模式

❌ 缺少 import 或注解
❌ 代码无法编译
❌ 空文件或 "..." 占位符代码
❌ 缺少全局组件（异常处理、健康检查）
❌ 迁移脚本有 SQL 语法错误
❌ 未记录设计理由
