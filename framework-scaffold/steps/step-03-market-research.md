# 步骤 3：市场调研与对标

## 强制执行规则（必须先完整阅读）

- 📖 关键：必须完整阅读本步骤文件后再执行任何操作
- ✅ 所有建议必须基于经过市场验证的解决方案
- 🌐 必须通过网络搜索验证当前版本和选项
- 💬 专注于找到相关的对标系统和已验证的模式
- ✅ 所有输出使用中文

## 执行协议

- 🌐 使用网络搜索查找当前最佳实践和成熟方案
- 📊 找到 2-3 个相似场景的参考系统
- 📝 记录所有发现和来源
- 📖 加载下一步前更新 frontmatter：`stepsCompleted: [1, 2, 3]`

## 上下文边界

- 步骤 1-2 的需求文档已确认且可用
- 技术栈方向已明确（可能宽泛如"Java 生态"或具体如"Spring Boot 3.3"）
- 专注于市场调研，不做最终架构决策

## 你的任务

调研市场上经过验证的框架、架构和模式，找到参考系统，识别最佳实践，为架构设计提供依据。

## 调研序列

### 1. 确定调研范围

基于确认的需求，确定调研领域：

- **目标技术栈**：该领域常用哪些框架、库和工具？
- **相似项目**：有哪些开源项目或公开架构解决了类似问题？
- **行业模式**：这类系统有哪些经过验证的架构模式？
- **规模考量**：预期规模下有哪些成熟的解决方案？

### 2. 搜索参考系统

使用网络搜索找到 2-3 个参考系统：

```
搜索："{{项目类型}} {{技术栈}} 开源项目 生产架构"
搜索："{{相似业务领域}} 系统架构 {{技术栈}}"
搜索："{{技术栈}} 生产最佳实践 {{当前年份}}"
```

对每个参考系统，分析：
- **相似场景**：与本项目有何相似之处？
- **架构方式**：使用了哪些模式和结构？
- **关键借鉴点**：我们能学到什么？
- **需要适配的部分**：哪些需要根据本项目做调整？

### 3. 调研行业实践

搜索当前最佳实践：

```
搜索："{{技术栈}} {{项目类型}} 最佳实践 {{当前年份}}"
搜索："{{技术栈}} 项目结构规范"
搜索："{{技术栈}} 生产环境检查清单"
```

### 4. 验证技术版本

对目标技术栈，验证当前稳定版本：

```
搜索："{{框架}} 最新稳定版本"
搜索："{{框架}} 当前 LTS 版本"
搜索："{{数据库}} 生产推荐版本"
```

## 成功标准

✅ 分析了 2-3 个参考系统并评估了相似度
✅ 通过网络搜索验证了当前技术版本
✅ 记录了行业最佳实践及来源
✅ 创建了包含思考过程的市场调研文档
✅ 关键借鉴点与本项目需求明确关联
✅ 识别了反模式和常见陷阱

## 失败模式

❌ 未通过网络搜索验证当前版本
❌ 推荐过时或已停止维护的方案
❌ 调研发现未与本项目具体需求关联
❌ 创建了泛泛而谈的调研，没有具体的借鉴点
❌ 未记录来源
❌ 未记录思考过程
