# crafting-quality-code

> 模拟资深工程师写代码时的质量内审机制。每写一段代码，自动按质量维度审视并修正。满足需求前提下尽量简单，不为假设的未来设计。

## 这个 Skill 能做什么

你说一句"帮我写一个支付函数"或"重构这个类"，它会：

1. **确定代码角色** — 核心逻辑 / 公开 API / 内部工具 / 胶水代码，不同角色质量侧重不同
2. **按维度审视** — 正确性、可读性、健壮性、低耦合、适度扩展 + 现代 Java / LLM 集成 / 微服务，根据角色选择侧重
3. **编码并自检** — 写完代码后逐项自检，发现问题立即修正，直到全部通过

## 怎么用

在 Claude Code 里说以下任何一种就能触发：

- "帮我写一个用户注册函数"
- "重构 OrderService 这个类"
- "写一段生产级代码"
- "用高质量标准写这个模块"

## 工作流程

```
理解需求 → 确定代码角色 → 选择质量侧重 → 编写代码 → 自检修正 → 输出
     ↑                                                    |
     └──────── 发现问题，修正后重新检查 ←───────────────────┘
```

## 质量维度

| # | 维度 | 一句话 | 适用场景 |
|---|------|--------|---------|
| 1 | **正确性** | 逻辑符合规约，边界处理完备 | 所有代码 |
| 2 | **可读性** | 命名表意，结构清晰，注释适度 | 所有代码 |
| 3 | **健壮性** | 防御外部输入，异常分层，资源释放 | 处理外部数据/网络/文件 |
| 4 | **低耦合** | 单一职责，依赖可注入，修改局部化 | 类/模块级别 |
| 5 | **适度扩展** | 面向接口，避免写死，但不提前抽象 | 核心业务逻辑/公开 API |
| 6 | **现代 Java** | Record、Sealed Class、虚拟线程、模式匹配 | Java 17+ 项目 |
| 7 | **LLM 集成** | 超时控制、降级处理、提示词管理 | 调用 AI/LLM 服务 |
| 8 | **流式资源** | 流式传输、资源释放、内存控制 | 文件处理/大响应 |
| 9 | **策略工厂** | 策略接口 + @PostConstruct Map 注册 | 类型路由/多策略场景 |
| 10 | **SSE 流式** | 连接生命周期、心跳保活、错误恢复 | 实时推送/LLM 流式输出 |
| 11 | **LLM 模型路由** | 多 Provider 路由、模型缓存、降级链 | 多模型/多场景 LLM |
| 12 | **异步事务** | 事务后异步、CompletableFuture 超时、批量并发 | 耗时操作异步化 |

不是所有代码都要 12 维度全上。核心业务逻辑全上，内部工具只看正确性和可读性就够了。

## 特色功能

- **角色分级** — 根据代码角色自动调整质量侧重，不搞一刀切
- **跨语言通用** — 规则不绑定特定语言，代码示例覆盖 Python / Java / TypeScript
- **自检闭环** — 写完自检，发现问题立即修正，修正部分重新检查
- **适度设计** — 明确"过度设计比适度设计危害更大"，防止抽象过度
- **现代 Java** — 覆盖 Java 17+ 特性（Record、Sealed Class、虚拟线程、模式匹配）
- **LLM 集成** — 覆盖 AI 服务调用质量（超时、降级、结构化输出）
- **微服务** — 覆盖服务间通信、配置管理、缓存策略
- **策略工厂** — 覆盖策略注册、工厂路由、开闭原则实践
- **SSE 流式** — 覆盖 SSE 连接管理、心跳保活、集群广播
- **LLM 路由** — 覆盖多模型选择、模型缓存、降级链
- **异步事务** — 覆盖事务后异步、CompletableFuture 超时、批量并发
