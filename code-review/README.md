# code-review

> 对代码进行专业审查，覆盖正确性、安全性、性能等 10 个维度。不确定的问题主动提问确认，分三步输出审查报告、修复建议、修改后的代码。

## 这个 Skill 能做什么

你说一句"帮我审查这段代码"，它会：

1. **审查代码** — 按指定维度（默认全部 10 个）逐项检查，发现问题分级（阻塞/严重/建议/待确认）
2. **提问确认** — 不确定的问题集中提问，避免武断下结论
3. **生成修复建议** — 按优先级排列修复方案，含修复前后对比
4. **执行修改** — 输出 diff 补丁和修改对照表

## 怎么用

在 Claude Code 里提交代码并说明语言即可触发，例如：

- "帮我审查这段 Java 代码"
- "审查这个 PR 的 diff，语言 TypeScript"
- "对 src/service.py 做个 quick 审查"

## 工作流程

```
第一步：审查 → 提问 → 输出审查报告
  "帮我审查这段代码"
        ↓ 按维度检查、发现问题、提问确认
        ↓ 输出审查报告（写入 docs/review/code-review-report.md）
第二步：修复建议
  "生成修复建议"
        ↓ 按优先级排列修复方案
        ↓ 写入 docs/review/fix-recommendations.md
第三步：执行修改
  "修复 ISSUE-001 和 ISSUE-003"
        ↓ 输出 diff 补丁和修改对照表
        ↓ 写入 docs/review/fixed-code.md
```

每一步都可以停下来，不需要走完全部三步。

## 文件结构说明

```
code-review/
│
├── SKILL.md              ← 入口文件，定义角色、审查维度、工作流规则
├── customize.toml        ← 配置文件（可改默认 effort、输出目录等）
└── README.md             ← 本文件
```

## 输出文件

所有输出写入**被审查项目**的 `docs/review/` 目录（可通过 `customize.toml` 修改）：

```
你的项目/
└── docs/review/
    ├── code-review-report.md      审查报告（第一步）
    ├── fix-recommendations.md      修复建议（第二步）
    └── fixed-code.md               修改后的代码（第三步）
```

## 审查维度

| # | 维度 | 说明 |
|---|------|------|
| 1 | 正确性 | 逻辑 bug、边界条件、类型安全 |
| 2 | 健壮性 | 异常处理、输入校验、资源释放 |
| 3 | 安全性 | 注入、XSS、敏感信息、不安全加密 |
| 4 | 性能 | 算法复杂度、N+1、内存泄漏 |
| 5 | 可读性 | 命名表意、函数长度、注释质量 |
| 6 | 可维护性 | 单一职责、魔法数字、耦合度 |
| 7 | 可扩展性 | 面向接口、开闭原则 |
| 8 | 可测试性 | 依赖可注入、副作用隔离 |
| 9 | 风格一致性 | 语言风格指南、项目内一致 |
| 10 | 文档 | 公开函数文档注释 |

## Effort 级别

| 级别 | 审查范围 | 适用场景 |
|------|---------|---------|
| `quick` | 4 个核心维度（正确性、健壮性、安全性、性能） | 快速过一遍、CI 卡点 |
| `standard` | 全部 10 个维度 | 日常审查 |
| `thorough` | 全部 10 个维度 + 交叉关联分析 | 上线前、安全审计 |

## 特色功能

- **断点续检** — 会话中断后重新触发，自动检测已有审查文件，从断点继续
- **提问确认** — 不确定的问题集中提问（不超过 5 个），避免武断
- **分级输出** — 发现少时精简输出，发现多时完整报告
- **三步可控** — 每一步都可以停下，用户决定是否继续

## 自定义配置

编辑 `customize.toml`：

```toml
[workflow]
communication_language = "中文"
document_output_language = "中文"

[review]
default_effort = "standard"       # quick / standard / thorough
focus_areas = []                  # 空为全扫，如 ["security", "robustness"]

[output]
docs_dir = "docs/review"          # 输出目录（相对于项目根目录）
```
